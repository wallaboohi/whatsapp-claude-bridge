## 1. איך מוציאים טיוטה לאישור (לכל בינה)
1. שולחים לאדם או לקבוצה אחרת רק כך: כלי `send_message` של הגשר (MCP), או מהמעטפת `uv run --no-project python tools/wa_send.py <נמען> <קובץ-טקסט-UTF8>` מתיקיית השורש של הכלי (`C:/Users/walla/whatsapp-mcp`).
2. במצב טיוטה (ברירת מחדל) הגשר לא שולח. הוא יוצר טיוטה ומפרסם *בעצמו* כרטיס אישור בקבוצה שבה אתה עובד: נוסח ההודעה המלא, והקובץ המצורף כהודעה נפרדת "קובץ לטיוטה". כרטיס שחסר או שיקיר ביקש לראות שוב: `uv run --no-project python tools/wa_draft_card.py <מספר טיוטה>` (נבנה 15.11; מפרסם שוב את הכרטיס עם הנוסח המלא והקובץ, בלי ליצור טיוטה חדשה). אסור ליצור טיוטה כפולה בשביל "לשלוח שוב".
3. אחרי יצירה אומרים ליקיר בקצרה: "הטיוטה ל<שם הנמען> ממתינה לאישור בכרטיס". לא כותבים שליחה שלא קרתה, ולא שולחים אותו לחפש ביומן.
4. הכרטיס חסר? בודקים `list_drafts` (סטטוס pending) ומריצים `wa_draft_card.py` לפרסום מחדש. טיוטה שכבר pending לא נוצרת שוב אלא אם יקיר ביקש במפורש כפילות.
5. בכרטיס מופיע הנוסח המלא כפי שיישלח, בלי קיצור (כלל "מלוא נוסח לפני אישור").
   *כלל בסיס (יקיר 15.11):* בכל טיוטה מוכנה, התשובה ליקיר כוללת גם את הנוסח המלא ומודיעה שהכרטיס נשלח, כדי שיראה על מה לאשר (✅/❌).
6. אישור = הודעה אחת לנמען אחד. החלפת מצב לשליחה אוטומטית רק בהוראה מפורשת ומוגבלת בזמן של יקיר (`whatsapp-bridge/store/send_policy.json`). אם `paused_until` בעתיד, ווצאפ מגביל את החשבון: לא עוקפים, מדווחים.
7. טיוטה רק כשיקיר ביקש במפורש לנסח או לשלוח הודעה לאדם. "תעזור עם הבקשה של X" פירושו לברר ולהציג ממצאים. אסור ביוזמה, ובמיוחד לא לריטה.
8. חתימה קבועה בטיוטות של אוטומציית מקטע D בלבד (פירוט והיקף ב-`bridge_rules.md`).
9. שליחה לנמענים עם מדיה/קובץ: הקובץ נשמר ב-`agent/home/outbox/` ונשלח אחרי התשובה. קובץ שיקיר שלח מגיע כ-`[attached file: <path>]` וקוראים אותו משם.
10. הודעות עשירות (אירוע עם RSVP, תיוג, מיקום): `tools/wa_rich.py <jid> event|mention|location '<json>'`, באותם כללי טיוטה.

- *רכיב חדש בלוח הבקרה:* לשאול איפה למקם לפני שבונים; לא להזיז רכיב קיים. שינוי בלוח נבדק בחלון האמיתי שיקיר רואה (`WhatsAppDash.exe`), לא רק ב-8770, ובכל פקודה וכפתור.

## 5. כלי המעטפת של הגשר (תיקיית `tools/` בשורש `C:/Users/walla/whatsapp-mcp`)
הרצה מהשורש: `uv run -q --no-project python -I -X utf8 tools/<כלי>.py ...`. טקסט בעברית תמיד מקובץ UTF-8 ולא משורת הפקודה (קונסולת Windows הופכת אותו ל-`????`).
- `wa_send.py <נמען> <קובץ>`: הודעה לאחר כטיוטה. `wa_rich.py <jid> event|mention|location '<json>'`: אירוע עם RSVP, תיוג ומיקום (באותם כללי טיוטה).
- `wa_draft_card.py 34`: פרסום מחדש של כרטיס טיוטה ממתינה (נוסח מלא + קובץ), בלי טיוטה חדשה.
- `wa_draft_cancel.py 24 25 30-42`: ביטול טיוטות ממתינות בלבד. אישור ושליחה נשארים ליקיר (✅ בכרטיס).
- `wa_remind.py add <קובץ> --at "YYYY-MM-DD HH:MM"` או `--in <דקות>` או `--noreply <jid> --hours N`; `list | done | cancel | snooze`. תזכורת רק ליקיר.
- `wa_push.py "<עד 90 תווים>"`: התראת פוש. רק כשיקיר לא בשיחה איתך ושאלה מחכה לו.
- `wa_history.py <jid> [--until YYYY-MM-DD] [--before <message_id>]`: טעינת היסטוריה ישנה מהטלפון, בלי לשאול קודם.
- `wa_admin.py /api/<נקודה> <json>`: נקודות ניהול של הגשר (כולל `/api/get_picture` עם `{"jid": ...}`). לא להעביר עברית בשורת הפקודה.
- `gsheet.py tabs | values "<לשונית>" [טווח] | dump <out.json> | export <out.xlsx> | revisions | activity [N]`: גיליון החברה של מקטע D, *קריאה בלבד* (הרצה עם `--with google-auth --with requests`).
- `gsheet_write.py <changes.json>`: תצוגה מקדימה בלבד. כתיבה (`--approved`) רק אחרי שיקיר אישר שינויים ממוספרים מדויקים; `--undo <backup.json> --approved` מחזיר.
- `gmail.py`: חיפוש, קריאה ויצירת טיוטות במיילים של יקיר (`--with google-auth-oauthlib --with google-api-python-client`). אף פעם לא שולחים מייל: נוצרת טיוטה ויקיר שולח.
- כלי MCP של הגשר (לכל בינה מתארחת עם CLI): `list_messages`, `search_all`, `get_message_context`, `list_chats`, `get_chat`, `search_contacts`, `get_group_info`, `list_drafts`, `list_polls`, `list_transcripts`, `download_media`, `get_status`, וגם `send_message`, `send_file`, `send_audio_message`, `react_to_message`, `set_group_name` (שם קבוצה רק בבקשה מפורשת). כל שליחה לאחר היא טיוטה.
- בינה שאין לה גישה לכלי MCP (Qwen Code ומנועים דרך פרוקסי) קוראת הודעות רק דרך מה שהגשר מצרף, ושולחת רק דרך מעטפת אם יש לה.
- יכולות ייחודיות ל-Claude Code ללא תחליף אצל האחרות: סוכני משנה, Skills, WebSearch/WebFetch ומשימות מתוזמנות. כשבינה אחרת צריכה אותן, היא אומרת ליקיר שצריך להחליף ל-`/claude`.
   *בנייה והחלפת גשר, מותר לכל בינה, אבל רק דרך מנגנון הגשר (יקיר 15.11.2026, כלל בסיס לכל הגשר):* כל בינה רשאית לבנות מחדש ולהחליף את הגשר (`whatsapp-bridge.exe`) כשהקוד השתנה, ובתנאי שהיא עושה זאת דרך הפונקציה `agent._rebuild_bridge()` של המנגנון (בלפטופ עם `C:\msys64\ucrt64\bin` ב-PATH), או משאירה לשמירה היומית. הפונקציה בונה עם `-ldflags -X main.version=<VERSION>`, ולכן אסור `go build` ידני והעתקת קובץ הרצה בין המחשבים, שגורמים לגרסה `dev`. קודם קומיט ו-`push hub`. אחרי כל החלפה בודקים שהגרסה בשני המחשבים שווה ל-`VERSION`.
